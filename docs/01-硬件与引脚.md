### 时钟配置

`Drivers/CMSIS/device/system_n32g031.c` 默认值（**未修改**）：

```c
#define SYSCLK_FREQ  48000000
#define SYSCLK_SRC   SYSCLK_USE_HSI_PLL   /* 内部 8MHz RC + PLL → 48MHz */
```

**用内部 HSI，不需要外部晶振**。这一点很重要，因为 PF0/PF1 兼作 OSC_IN/OSC_OUT。

## 2. 引脚总表

| 功能 | 引脚 | 说明 |
|---|---|---|
| 调试串口 | **PA2 = TX**，**PA3 = RX** | **USART2 + `GPIO_AF4_USART2`**，时钟在 **APB1** |
| 传感器 I²C | **PF0 = SDA**，**PF1 = SCL** | **软件模拟 I²C**（未用硬件 I2C1） |
| OLED I²C | **PA6 = SCL**，**PA7 = SDA** | **软件模拟 I²C**（未用硬件 I2C2） |
| GP315 PWM | **PA4** | TIM3_CH1，`GPIO_AF2_TIM3` |

引脚定义来自用户提供的 `datum/引脚定义.txt`（已用 node 解密读出）。

### 为什么两根 I²C 都用软件模拟

1. 避开硬件 I²C 的 AF 映射和引脚重映射问题
2. 和商家提供的 OLED 例程写法保持一致
3. 两根总线可以共用同一份 `soft_i2c.c`，只是传入不同的 pin

### PF0/PF1 的特殊性（重要）

数据手册引脚表里这两个脚的默认名是：

```
PF0-OSC_IN (PF0)   → 复用功能有 I2C1_SDA；附加功能 OSC_IN, OPAMP_VINP
PF1-OSC_OUT (PF1)  → 复用功能有 I2C1_SCL, USART1_CK, USART2_CK；附加功能 OSC_OUT
```

- 它们**默认是外部晶振脚**，但因为时钟源选的是 HSI，HSE 没开，所以可以当普通 GPIO 用
- **如果板子上焊了晶振及其负载电容，会跟软 I²C 信号打架** —— 有的话拆掉
- 硬件 I2C1 的默认脚就是 PF0/PF1，但本工程用的是软件模拟，所以不涉及 AF

## 3. 电气要点

### 3.1 I/O 电平门限（数据手册表 4-26，已核对）

| VDD | VIH 最小（输入判高） | VIL 最大（输入判低） |
|---|---|---|
| **5 V** | **0.7 × VDD = 3.5 V** | 0.3 × VDD = 1.5 V |
| **3.3 V** | **2.0 V** | 0.8 V |
| 1.8 V | 0.8 × VDD = 1.44 V | 0.2 × VDD |

### 3.2 供电电压怎么选（踩过的分析）

| 方案 | 结果 |
|---|---|
| 主控 5V + I²C 上拉到 **5V** | 旧款 HBP5023D-1（3.6V 上限）会被打坏 ❌。**新款 -2 支持 5.5V，这个方案现在可行** ✅ |
| 主控 5V + I²C 上拉到 **3.3V** | 主控在 5V 下需要 3.5V 才算高电平，3.3V **不够** ❌ |
| **主控 3.3V + 上拉到 3.3V** | 两边都满足 ✅，最省事 |

**结论**：
- **HBP5023D-2 支持 1.8~5.5V（典型 5.0V）**，所以整板跑 5V 是可行的
- 但 **OLED 模块**很多只标 3.3V，上 5V 前必须确认模块规格
- GP315 的 PWM 输入要求 **2.7~5.5V**：3.3V 输出有 0.6V 余量（VOH 的 2.4V 最小值是带 8mA 负载时的规格，GP315 的 PWM 脚几乎不吃电流，实际接近 3.3V）

### 3.3 上拉电阻

| 总线 | 建议 |
|---|---|
| 传感器 SCL/SDA | **4.7 kΩ 到 Vddio**（-2 手册给的典型值） |
| OLED SCL/SDA | 模块通常自带；没有就 4.7k 到 3.3V |

代码里 `GPIO_PULL_UP` 也开了内部上拉（约 40kΩ）作兜底，但**太弱，不能替代外部 4.7k**。

### 3.4 GP315 供电

GP315 是**两线制环路芯片，VCC 8~30V（典型 24V）**，不是 3.3V 器件，**不能拿 3.3V 给它供电**。
它内部的 5V LDO 带载只有 10mA，**不要用来给主控供电**（主控 48MHz 就要 5~8mA，再加 OLED 就超了）。

## 4. ⚠️ PA4 定时器通道争议（**上板必须确认**）

这是本工程唯一没能在文档层面拍死的问题。

| 来源 | 说法 |
|---|---|
| **用户确认** | **TIM3_CH1** |
| 数据手册表 3-1（PA4 行） | 复用功能列里 **`TIM1_CH1`** 和 **`TIM3_CH1`** 都出现过 |
| 官方库 `TIM/Cascade_Synchro`（代码 + readme） | "PA4 选择为 TIM3 CH1 输出"，`GPIO_AF2_TIM3` |
| 官方库 `TIM/PWM_Output` | PA6/PA7/PB0/PB1 = TIM3 CH1~4 |

**当前实现**：`GPIO_AF2_TIM3` + TIM3_CH1（跟用户确认和 `Cascade_Synchro` 一致）。

**用法**：`gp315.h` 里

```c
#define GP315_USE_TIM1_CH1   0     /* 改成 1 就切到 TIM1_CH1（GPIO_AF2_TIM1，已写好分支） */
```

注意 TIM1 是高级定时器，**切换后必须调 `TIM_EnableCtrlPwmOutputs(TIM1, ENABLE)`** —— 代码里已按这个宏条件编译好了。

**验证方法**：烧录后示波器看 PA4 有没有 1kHz 方波。

## 5. 官方库 API 备忘（容易记错的地方）

```c
/* GPIO */
GPIO_InitStruct(&init);                   /* 先清零 */
init.Pin        = GPIO_PIN_4;
init.GPIO_Mode  = GPIO_MODE_OUTPUT_OD;    /* OD 的编码是 0x11，bit4 是开漏标志 */
init.GPIO_Pull  = GPIO_PULL_UP;
init.GPIO_Current = GPIO_DC_LOW;
init.GPIO_Alternate = 0;
GPIO_InitPeripheral(GPIOA, &init);

/* TIM —— 注意结构体初始化函数名，以及比较寄存器叫 CCDAT */
TIM_InitTimBaseStruct(&tb);
TIM_TimeBaseStructure.Period / Prescaler / ClkDiv / CntMode
TIM_InitTimeBase(TIM3, &tb);

TIM_InitOcStruct(&oc);
TIM_OCInitStructure.OcMode / OutputState / Pulse / OcPolarity
TIM_InitOc1(TIM3, &oc);
TIM_ConfigOc1Preload(TIM3, TIM_OC_PRE_LOAD_ENABLE);
TIM_ConfigArPreload(TIM3, ENABLE);
TIM_Enable(TIM3, ENABLE);
TIM3->CCDAT1 = compare;                   /* ← 不是 CCR1 */

/* 定时器计数时钟 = SystemCoreClock / (Prescaler + 1) */
```

**N32G031 有这些定时器**：TIM1、TIM2、TIM3、TIM6、TIM8、TIM18。
**没有 TIM14**（STM32F0 上有，容易惯性思维搞错）。
