## 1. ⚠️ DLP 加密（接手第一件要知道的事）

公司电脑装了 DLP/加密系统。**`.pdf` 和 `.txt` 落地即加密**，非白名单进程读出来是乱码：

```
文件头：17 DA 5F A0 16 33 CD 9A ...（后面全是密文）
```

**关键特性：加密状态跟着文件走** —— 复制、重命名、上传、base64 编码、放进压缩包，
**都不会解密**。所以「让用户上传 PDF」这条路是死的（已实测：用户上传的 PDF，
base64 解出来开头就是加密头）。

### 哪些文件类型**不**加密

| 类型 | 是否加密 | 说明 |
|---|---|---|
| `.c` / `.h` | ❌ 不加密 | **代码可以直接读写** |
| `.md` | ❌ 不加密 | 本文档就是 |
| `.png` / `.jpg` | ❌ 不加密 | **截图可以读** |
| `.json` | ❌ 不加密 | |
| `.log` | ⚠️ 视进程而定 | python.exe 写的 `.log` 会被加密 |
| `.pdf` | ✅ 加密 | |
| `.txt` | ✅ 加密 | **但 `node.exe` 能解密！** |

### 读加密文档的可行路径（按优先级）

| # | 方法 | 适用 |
|---|---|---|
| 1 | **翻已有提取目录**（见第 2 节） | 最省事，很多文档已经提取好了 |
| 2 | 让用户**复制文字直接贴** | 最准，适合短文档/表格 |
| 3 | 让用户**打开后截图发 PNG** | 适合有图表的页面 |
| 4 | 让用户在 **TRAE** 里提取成 `.md` | 适合长文档，用户已有成熟流程 |
| 5 | **`node.exe` 读 `.txt`** | 唯一能程序化解密 `.txt` 的途径 |

### 已验证**不可行**的方法（别浪费时间）

- ❌ `pdftotext` / 任何 PDF 解析库 —— 读到的是密文
- ❌ `node.exe` 读 PDF —— 解不开（读 `.txt` 可以，PDF 不行）
- ❌ 上传 PDF 给 AI —— 加密跟着文件走
- ❌ Edge headless 截图 PDF —— 渲染不出来（和加密无关，是 headless 不支持 PDF 插件）
- ❌ `PrintWindow` 抓 WPS 窗口 —— 返回空白（GPU 合成）
- ⚠️ 屏幕截图 WPS 窗口 —— 技术上可行（PDF 里的字能读到），但**窗口焦点极不稳定**，
  其它窗口（浏览器/Keil/VS Code/Claude 自己）会不断抢到前面，实测非常难自动化

### `node.exe` 解密 `.txt` 的用法

```bash
"D:/Node.js/node.exe" -e "
const b = require('fs').readFileSync('D:/path/to/encrypted.txt');
console.log(b.toString('utf8'));
"
```

本项目就是这么读出 `datum/引脚定义.txt` 的（185 字节明文，磁盘上却是 1209 字节密文）。

```
├── GPIO/  ADC/  SPI/  LPTIM/  RTC/  COMP/  OPA/  BEEPER/  DMA/  FLASH/ ...
```

### 怎么从例程里挖信息

**例程是最靠谱的「这个芯片到底怎么用」的来源**，尤其是：

```bash
# 找某个引脚配成某个复用功能的写法
grep -rn "GPIO_PIN_4" <库>/examples/TIM --include=main.c -B4 -A4

# 例程目录下的 readme.txt 经常直接说明引脚用途
cat <库>/examples/TIM/Cascade_Synchro/readme.txt
```

> 例程的注释/readme 也**不是 100% 可信** —— `Cascade_Synchro` 的 readme 说 PA4=TIM3_CH1，
> 而数据手册说 PA4 也支持 TIM1_CH1。**遇到冲突时以数据手册为准，最终以上板实测为准。**

## 5. 编译环境

| 项 | 值 |
|---|---|
| IDE | Keil MDK **V5.43a**（µVision） |
| 编译器 | **ARMCC V5.06 update 6 (build 750)** |
| Keil 路径 | `D:/keil/UV4/UV4.exe` |
| DFP | Nationstech.N32G031 |
| 优化 | -O1 |

### 命令行编译

```bash
cd D:/code/DP_transmitter/code/N32G031_DP_transmitter
"D:/Keil/UV4/UV4.exe" -b "N32G031_DP_transmitter.uvprojx" -j0 -o "build.log"
```

**编译日志是明文**（Keil 在 DLP 白名单里），可以直接 grep：

```bash
grep -E "error|warning|Error\(s\)" build.log
```

> 注意：µVision 图形界面**可以同时开着**，命令行编译不冲突。

### 往工程里加新文件

需要**手动改 `.uvprojx`** 的 `<Groups>` 段，格式：

```xml
<File>
  <FileName>xxx.c</FileName>
  <FileType>1</FileType>
  <FilePath>.\User\Src\xxx.c</FilePath>
</File>
```

放在对应的 `<Group>` / `<Files>` 里。
**漏了这步会编译不到该文件，表现为链接时 `undefined symbol`。**

## 6. 烧录与调试

| 项 | 值 |
|---|---|
| 烧录 | Keil → Flash → Configure Flash Tools → Utilities，勾 **Reset and Run** |
| 调试器 | 工程里配置的（J-Link / DAP） |
| 串口工具 | 任意（115200 8N1），例：SSCOM / 串口助手 |

### 串口看不到输出时

1. 确认 **PA2 = TX** 接到了 USB-TTL 的 **RX**
2. **波特率 115200 8N1**
3. 量 PA2 有没有波形（有波形说明 MCU 在跑，是接线/端子问题）
4. 确认 `USART_Debug_Init()` 被调用了（在 `main()` 第一行附近）

## 7. 其它环境备注

- Shell 是 **Git Bash**（POSIX sh），不是 PowerShell
- Python 可能不可用（Windows Store stub 问题）—— 需要脚本时优先用 **`D:/Node.js/node.exe`**
- `D:/Node.js/node.exe` 是 Node v24，**既能解密 `.txt`，也是写文件不触发加密的可靠工具**
- 逻辑分析仪（Logic2）可用 MCP 连接：`POST http://127.0.0.1:10530/mcp`
  —— 如果 SCO 问题查不下去，**建议用它抓一次 I²C 波形**
